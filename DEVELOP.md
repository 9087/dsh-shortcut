# Developing dsh-shortcut

Two halves, two bundles, one package:

| Half | Source | Output | Runs in |
|---|---|---|---|
| Host | `src/index.ts`, `src/store.ts`, `src/share.ts`, `src/types.ts`, `src/atomic-write.ts` | `lib/index.js` | the `dsh` host process (Node) |
| Client | `src/client/**` (React + CSS module) | `lib/client.js` | the DSH Web page (browser) |

They talk over this plugin's own connection channel `'/shortcut'` (`list / create / update / remove / send`). The host owns the durable store and delivery; the browser owns every surface.

## Targets and delivery

A record addresses one **agent**, stored as `{ kind: 'main' | 'subagent' | 'member', childSessionId?, leafLabel?, path? }` next to the owning `sessionId`. `kind: 'main'` means the session's own agent; the other two are continuable direct-child sessions (a subagent, or an agent-team teammate, which is also a continuable child of the Lead).

Delivery therefore has two paths (`src/index.ts`):

- `main` → `ctx.sessionController.prompt({ requestId, sessionId, mode: 'queue', content })`, which resumes a cold session and persists the message;
- `subagent` / `member` → `ctx.subagents.prompt({ requestId, parentSessionId: sessionId, childSessionId, mode: 'continuable', delivery: 'queue', content })` — the same call the app makes for browser-authored child messages. It requires the child's DIRECT parent session to be live; one-shot children reject with `subagent/not-resumable`. Both are surfaced as `target-not-resumable` / `parent-unavailable`.

The host `sendFailure()` also recognizes the session API's subagent-routing refusal (`session/agent-busy` with the `use subagent delivery` reason) so it is never misreported as "session busy".

## What each half does

**Host**

- `src/store.ts` — `<DSH_HOME>/shortcut/entries.json` (v2 envelope `{ version: 2, entries }`), loaded once, mutations serialized, written via temp-file + rename with Windows `EPERM` retries (`src/atomic-write.ts`). v1 records are read as main-agent targets and rewritten as v2 on the next write. A corrupt/unreadable file answers `store-unavailable` instead of an empty list.
- `src/index.ts` — mounts the RPC channel on `ctx.connection`, and delivers a record by the path above. Services (`sessionController`, `subagents`) are resolved lazily with `ctx.get`, so the plugin still boots where the subagent runtime is absent. Failures are classified (`session-not-found`, `session-archived`, `session-busy`, `target-not-resumable`, `parent-unavailable`, `target-unavailable`, `no-current-session`, `send-failed`). **An `anySession` record is addressed by the CALLER, not by the store**: `send` carries the conversation the caller has open, delivery goes to THAT conversation — a top-level session through the session controller, or a subagent/team member opened as its own conversation through the `subagents` runtime, which needs the parent the caller sends as `currentParentSessionId` — and a caller that named none is refused with `no-current-session` instead of being redirected to the stored session, because that fallback is exactly what the switch turns off. The receipt names the address that actually received the text (parent + child target for a child, the session itself otherwise), so a client that navigates afterwards follows it to the right place. **`suggestName` names a prompt**: it asks the default model for a one-shot title (`ctx.llm.stream` called with `ctx.agentDefaultModel.currentSelection()`), reads the answer with `visibleTextOf` (tolerant of `text`/`delta.text`/`content.text`/`block-end`, and it **never** counts `reasoning-delta` as the answer), and falls back to the deterministic rule whenever the runtime, the selection or the provider is unusable — so the dialog's button never depends on a model being configured. The call is deliberately shaped like `dsh-shell-progress`'s working notes call: **`reasoningEffort: 'off'`** (this host runs `high`, and thinking spends the token budget and can leave the answer with no visible text at all), `maxTokens` 256 rather than a tight cap, and a 12s deadline that **races** the stream instead of only aborting it (an adapter ignoring the signal would otherwise keep the button spinning). **A delivery to a top-level session wakes the agent through the native seam** — `sessionController.resolveAgent` → `agent.followup(createUserMessage-shaped message)` → `sessions.flush` — instead of `prompt`, because a message that WAKES an idle agent is what the shell renders as its trigger card; the message is tagged `source: { kind: 'shortcut', … }` and its **text is the prompt verbatim** (the card is the packaging, not the message), so the card names the record. The `prompt` path stays as the fallback for a host without that verb, and subagent targets keep the subagent runtime (a child delivery has no waking message, so no card). **The language is taken from the prompt text itself** (the dialog's 提示词 field), never from the UI locale: `languageTagOf` reads that text's dominant script — a CJK share of at least 20% with at least two CJK characters, so "帮我 review 这个 PR" is Chinese while "add a retry to the 微信 upload client" is not — the system prompt carries the concrete BCP-47 tag (`zh`/`ja`/`ko`, or an explicit "mirror the prompt" rule for the other scripts), and `languageMismatch` refuses an answer that came back in the other script family. A Chinese prompt titled in English is a refusal with a note, never a name. It differs in one place: the reference takes the provider/model from `exec.agent.options` — the route of the agent doing the work — and a dialog has no such agent, so this uses the host's default selection, which is what a new agent would be given. A declined call is answered with a `note` (the provider's own message) that the dialog turns into a toast, and the refusal **writes nothing into the name field** — the model path must never degrade silently, or "it did not use the model" is indistinguishable from a bug, and a quietly filled prefix looks like success.
- `src/share.ts` — the draft rules both halves run (blank/length/duplicate-name, and target shape: `main` must have no child, subagent/member must have one, distinct from the session). **Only the NAME is length-capped (60); the text is not**, matching the host's reminder prompt rule (`ctx.schedule` accepts a prompt on the single condition "non-empty after trimming") — a cap here would refuse text the rest of the product accepts. It also owns the naming rules as pure functions: `suggestName` (the deterministic fallback: first non-empty line, list/heading markers and paired wrappers stripped, word-boundary cut at 40), `cleanName` (a model answer turned into a label: first line only, `标题：`/`Title:` labels, markdown emphasis, sentence punctuation, and wrappers removed **in pairs** so a name ending in `）` is not mangled), and `uniqueName` (de-duplication against the other records inside the 60 cap, never against the record being edited). Both switches normalize with the same polarity rule: only an explicit `false` turns `navigate` off, only an explicit `true` turns `anySession` on, so a draft from an older client keeps the safe default.

**Client** (`src/client/`)

- `index.ts` — `apply()`: registers the locale dictionaries, binds the RPC port, starts the catalog subscriptions, fills three seats and starts the bubble DOM bridge.
- `catalog.ts` — the shared data layer: subscribes once to `ctx.get('sessions').list` and `ctx.get('workspaces').list`, builds the picker input, resolves the target path (`<workspace> / <session>` for a main agent, plus the leaf for a child) for settings rows and toasts, and calls `sessions.refreshProjections(sessionId)` on demand (the `subagentCatalog` / `agentTeam` projections are NOT persisted, so an unloaded projection means "children unknown", never "no children").
- `picker-tree.ts` — the pure workspace → session tree: sessions come from `WorkspaceView.sessionIds`, and a session's child agents from its `subagentCatalog` plus `agentTeam` roster. **A session row IS its main-agent target** (selecting it yields `{ kind: 'main' }`); only expanding it reveals subagent/team-member leaves. An expand chevron is drawn only for a known non-empty branch, so a leaf never looks expandable while its catalog is still loading; one-shot/unknown-mode subagents and non-active team members are disabled with a reason. Each agent row also carries its `ancestors` session-id chain, which the editor stores so a saved target can be re-expanded and scrolled to on reopen. Unit-tested in `tests/picker-tree.spec.ts`.
- `components/SessionTreePicker.tsx` — the inline picker rendered inside the dialog (a read-only full-path line, search, session rows selecting the main agent, separate expand buttons, on-demand projection loading/prefetch, the native folder icon on grouping-only workspace rows, and the reopen-reveal effect: expand the stored `ancestors` chain and `scrollIntoView` the selected row). No popover/portal.
- `components/FooterEntry.tsx` — the sidebar-foot trigger + menu (`sidebar.footer.action`, order 90 — it only has to be in that list, which the shell draws above its Settings row; adjacency is explicitly not a requirement, since other footer plugins insert rows too), and the single host for the shared dialog/banner.
- `menu-groups.ts` — the menu's grouping, pure and unit-tested: records are split into three groups drawn in this order — `current` (bound to the session the page is SHOWING, via `useCurrentSessionId` from the session seat), `any` (records marked sendable to any session, which belong to no session and so never join either session group), and `other`. A heading is a `MenuLabel`, which the shell renders as a non-interactive `role="presentation"` row in its tertiary label color — so "always expanded" needs no state, and there is no second level yet. A heading is drawn only for a non-empty group, and no heading at all is drawn when no session view is mounted (the Settings page), because then no session group means anything and store order is the honest flat list.
- `components/SettingsSection.tsx` — the Settings page (`settings.section`, id `shortcut`), showing each record's full target path.
- `components/EditorDialog.tsx` — the one add/edit dialog (name, target tree, **prompt**, and two switches: `navigate` and `anySession`) in a wide two-column layout (tree left, message body right; the tree list scrolls at ~200px so the dialog stays short). The name row also carries **generate from prompt**: a host round trip (`suggestName`) that fills the name from the model's title and leaves the caret there — a starting point, never a silent overwrite. The button shows 生成中… while the call is in flight and is inert while the prompt is blank; when the model declines, **nothing is written** and a toast carries the host's own reason (so a dead model is never mistaken for a working one). Confirm is enabled only for a valid, non-duplicate draft; the host re-checks. **One target tree serves every flow**: a bubble capture only SEEDS the session (and the prompt) and reveals that row, so the reader can still retarget it before saving. Turning `anySession` on locks that tree (`SessionTreePicker`'s `disabled`) and puts "任意会话" in its path line, because the stored target no longer decides the delivery; turning it off hands the tree back.
- `components/SessionSeat.tsx` — an invisible session-scoped seat (`conversation.session.header.utilities`) that publishes the shown session id and the chat snapshot into `session-bridge.ts`, and renders a hidden `[data-dsh-shortcut-session]` marker.
- `bubble-capture.ts` — the DOM bridge. The stock chat view gives a user bubble's action row **no plugin slot**, so the "add to shortcut" button is injected as a sibling immediately before the copy button. Stable anchors only: `[data-chat-flow-kind="user"]`, `[data-clock="start"]`, `[data-chat-node-key]`. It is idempotent, self-heals after React re-renders (MutationObserver + rAF), skips optimistic bubbles, uses the copy button's own class for styling, and tears everything down on dispose.
- `trigger-titles.ts` — the second DOM bridge, and the other half of the delivery packaging. A delivery wakes the agent, so the shell draws it as ITS `turn-trigger` card, but that card's title comes from a closed switch over `source.kind` inside the shell (unknown → "收到执行请求"), with no seam to add a kind without taking over the renderer for every wake source. So this bridge retitles exactly OUR cards: `session-bridge` publishes `data-chat-node-key → shortcut name` for nodes whose source tag is ours, and the bridge rewrites that card's title to `快捷方式 · <name>` (icon, time, collapse behaviour and every other wake source untouched), re-applying after each React pass and on every bridge publish.
- `entries.ts` / `editor.ts` — module-level observable stores shared by every surface (menu, settings, dialog).

## Commands

```powershell
corepack pnpm install          # repo .npmrc pins registry.npmmirror.com (this machine)
pnpm run typecheck             # tsc -b (host + client)
pnpm run build                 # tsc -b && tsdown --env.DSH_BUILD_FACE client
pnpm test                      # vitest (unit: store, host delivery routing, port, validation, bridge, DOM bridge, picker tree, menu grouping)
pnpm run e2e                   # Playwright, real dsh web + throwaway DSH_HOME
pnpm run release               # release-it (bump/tag/push) then verify:release — see PUBLISH.md
node scripts/screenshots.mjs   # both READMEs' screenshots (own throwaway hosts; needs DSH_BIN)
```

`pnpm run build` must run before `pnpm run e2e`: the suite drives the built `lib/`, never the TS source.

Commit subjects are load-bearing: `pnpm run release` derives the next version from the conventional-commit prefixes since the last tag and generates `CHANGELOG.md` from them. A `feat:` / `fix:` / `perf:` subject changes the version; `docs:` / `chore:` / `build:` / `test:` does not (rules in [PUBLISH.md](PUBLISH.md#version-rules)).

## E2E

`e2e/shortcut.spec.ts` boots a private `dsh web` against a temporary `DSH_HOME`, links this checkout into that home's web profile (`e2e/helpers/host.ts`), and drives Chromium. It never touches the user's own DSH home or the GUI on 3080; `stopHost` kills only the child it spawned.

The suite needs a `dsh` executable: it resolves `DSH_BIN`, then a `PATH` shim, then the newest `npx` cache install. On this machine:

```powershell
$env:DSH_BIN = 'C:\Users\吴志伟\AppData\Local\npm-cache\_npx\b86ed90107c62dab\node_modules\@deepseek-ai\dsh\lib\bin.js'
pnpm run e2e
```

`E2E_TIMING=1` prints phase timings. `E2E_LOCALE=en` runs the same story against an English GUI
(the assertions accept either language). The suite deliberately does NOT write the README images:
a browser that dies mid-run must cost a test, never a doc artefact. They come from the separate
screenshot script below.

What it asserts: plugin activation (its own DOM, plus no `startup failed:` in the host log); the sidebar trigger sits in the footer action list above Settings; the bubble button is immediately left of copy; the capture dialog is seeded from the bubble, defaults BOTH switches off/on correctly (jump on, any-session off), shows an editable target tree seeded at that bubble's session (revealed there, and still answering a search), and stores the record (target `kind: 'main'`); the menu delivers into the original session and (with the jump switch on) navigates there, while a record with the switch off delivers without navigating; **the menu groups by the session on screen** (a record for another session sits under "其他会话" and moves under "当前会话" once that session is shown, each heading drawn only while its group has rows, in a lighter color than the rows and above them); **the any-session switch** moves a record out of the session groups into "任意会话", and triggering it there delivers into the session being viewed rather than the one it was captured from, then turning it back off restores the ordinary grouping; Settings edit (including turning the jump switch off), then add-by-hand through the **tree picker** (expand workspace → session, pick the main-agent leaf, row shows the full path), then delete; records survive a host restart.

The fixture has no model credentials, so a session's first turn fails fast. `settleTurn()` in `beforeAll` waits for that turn to settle before any test sends a shortcut: a message admitted while the only turn is still running goes into the agent queue and does not reach the durable log at the same moment, which made the delivery assertion depend on timing (the flake was only visible on slower runs). Sidebar-title probes are deliberately short (the shell truncates long generated titles), so an English run cannot miss a row whose title is cut before the probe's last word.

## Pitfalls this project already paid for

- **A plugin that fails to activate is a WARNING, not an exit** (`dsh: warning: N entries did not activate`); `dsh web` still prints its URL. Assert the plugin's own DOM — that is the real mount proof.
- **`dsh.client.inject` typos are silent**; a malformed `dsh.client` or a missing `exports["./client"].default` is a fatal boot (the `modules` entry is required).
- **No `@deepseek-ai/dsh-*` peer dependency is declared.** The 0.2.0-rc.2 install guard only accepts `^0.2.0-rc.2` ranges; declaring none (like `dsh-diff-approval`) sidesteps it and the host's services are resolved structurally.
- **The footer slot's roots are `display: contents`**; several footer plugins would be crammed into one flex row, so a stacking rule is injected (`index.ts`, deferring to `dsh-footer-order` when present).
- **Session logs are concatenated zstd frames**; `zstdDecompressSync` only decodes the first. The E2E therefore proves delivery through the GUI (open the target session and count its bubbles) rather than by decompressing the log.
- **`subagentCatalog` / `agentTeam` are not persisted projections.** A session's children are unknown until `sessions.refreshProjections(sessionId)` runs, so the tree treats "no projection yet" as *unknown* (an expandable session), never as *no children*. The picker asks on first expansion of a session or a subagent branch.
- **A child session is never deliverable through `sessionController.prompt`.** It answers `session/agent-busy` with a `use subagent delivery` reason; the host maps that (and `subagent/*`) to the target-specific error codes instead of "busy".
- **`aria-disabled` on a container disables its whole subtree for Playwright too** — worth knowing before reaching for it to make a surface read-only. `actionTimeout` is unset in this suite, so a `click()` inside such a subtree is retried until the TEST timeout: it hangs for minutes instead of failing, and the log only says "element is not enabled". Assert it with `expect(row).toBeDisabled()`, or force the press (`click({ force: true })`) and prove the component's own guard.
- **A rebuilt client bundle does not reach an open page by a plain reload.** Measured against a running host: the host recomputes the bundle revision from the file's mtime on every page request (its own HTML and a FRESH browser context both advertised the new revision after a rebuild), but the already-open page kept the old one, because the bundle is served `immutable` and the document itself can come back from cache. So: **client-half change → hard-refresh (Ctrl+Shift+R)**; **host-half change (`src/index.ts`, `store.ts`, and whatever they import at runtime) → restart `dsh web`**, since the process keeps the loaded module. `pnpm run dev:web` is the only loop that needs neither.
- **A model call that fails does not throw: it ends the stream with `finish` and `reason.kind === 'error'`.** The failure message is in `reason.failure.message` (e.g. `llm-deepseek: no API key for provider route …`). Code that only collects text deltas and ignores `finish` reads a refused call as an EMPTY answer — the fallback then runs silently and the user reports "it does not use the model" with nothing in the logs to contradict them. Handle the finish reason, and keep the failure visible in the UI.
- **`ctx.logger.info/warn` from a plugin does not reach the host's stdout log** in this build (a failing one-shot call and its warn line left `host.log` holding only the two boot banners). Do not plan a diagnosis around reading plugin logs: surface the reason on the wire (this plugin puts it in the `suggestName` payload's `note`) and show it in the UI.
- **The "automation task" card is the shell's generic `turn-trigger` node, not a schedule feature.** The client derives it from the turn's start: `start.event.type === 'user/message' && state.waking` → kind `turn-trigger`. So ANY message that wakes an idle agent renders as that card, and a delivery made while a turn runs is queued as a steering message instead (no card, it waits in the input area). Two limits worth knowing: the card starts **collapsed** (`useState(false)`), so only its title and time are visible until opened; and its title/icon come from a CLOSED switch over `source.kind` in the shell (`schedule`, `goal`, `webhook`, …) whose default is `message.trigger.request` ("收到执行请求") — an unknown kind such as `shortcut` gets the generic title. Overriding that means registering the `conversation.chat.node` renderer for the `turn-trigger` key, and that keyed slot REPLACES the renderer for every trigger kind, including the ones whose titles live in the shell's own locale namespace (the locale service cannot translate another namespace, so they could not be reproduced) — so this plugin retitles its OWN cards in the DOM instead (`trigger-titles.ts`).
- **A streamed adapter can deliver the same text TWICE: as deltas and again in `block-end`.** The DeepSeek adapter yields a `text-delta` per content delta and, at `content_block_stop`, a `block-end` whose `block` holds that block's COMPLETE text. A collector that appends both doubles the answer — a generated title came back as "重启 dev 服务重启 dev 服务". `block-end` text is a fallback only, for an adapter that streams no deltas (this plugin tracks which block indexes produced deltas).
- **Never kill a `dsh` process you did not start.**
